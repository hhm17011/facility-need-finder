# Architectural Issue Explorer

## 제품 방향과 모델 구분

시설 입력은 탐색의 맥락이다. 시설 부족이나 신축 필요성은 전제하지 않는다. 이전 Facility Demand Finder / Facility Need Finder의 수요·지역 순위 중심 제품 정의는 deprecated다. 저장소·패키지 이름은 호환성을 위해 유지한다.

주 흐름: 시설 이해 → 현상 탐색 질문 → 출처 탐색·근거 평가 → 현상 관계 검토 → 건축 이슈 선택 → 이슈에 연결된 지역 → 문제 정의.

- SOURCE: 검색 제공자가 반환한 제목·요약·원문 URL. 발견만으로 사실 확인이 되지 않는다.
- EVIDENCE: 출처에 연결된 정보와 평가. 현재 LIVE는 메타데이터 중심이다. `extractedClaims`는 원문 인용과 위치를 보존하는 확장 경계다.
- PHENOMENON: 자료에 기술된 변화·상태의 인용 후보. 검색 질문은 현상이 아니다.
- RELATIONSHIP: 현상 두 개 사이의 원문 관계 표현 또는 같은 문서의 언급. 동시 언급은 실제 동시 발생·상관·인과의 증거가 아니다.
- ARCHITECTURAL ISSUE: 현상 관계에서 공간·접근·분포·활동·활용의 질문이 있는지 검토할 후보.
- REGION: 관계 양쪽이 같은 지역을 명시할 때 연결되는 장소. 전국 현상을 지역에 투사하지 않는다.
- PROBLEM DEFINITION: 이슈와 지역의 확보된 주장을 인용해 설계 질문으로 정리한 편집 가능한 초안.

## 현상과 탐색 계획

`explorePhenomena(FacilityProfile)`가 이용자·기능·시설 이름으로 SOCIAL, DEMOGRAPHIC, URBAN, FACILITY, SPATIAL, USER, POLICY, ECONOMIC, ENVIRONMENTAL 질문을 만든다. 계획 UI의 주 단위는 이 질문이다. 법령·연구·보고서·조사·통계·기사 등 기존 7종은 질문을 확인할 출처 전략으로 보존한다. 기존 쿼리 제한·서버 순차 검색·캐시를 그대로 사용한다. 기본 유형당 2개 쿼리 제한 때문에 모든 세부 질문이 한 번에 검색되지는 않는다.

`Phenomenon`은 exact quote, category, direction, facility/users, evidenceIds, regions, scope, confidence, passages, status를 가진다. 규칙 분류는 정리용 라벨이며 의미 검증이 아니다. 혼합 방향·알 수 없는 방향은 UNKNOWN이다. 공백만 정리한 동일 문장을 같은 범위에서 합치며 원래 인용을 보존한다.

## 관계와 이슈의 보수적 경계

`analyzeIssues`는 같은 자료의 서로 다른 범주 문장 두 개를 연결한다. 서로 다른 지역의 두 문장, 전국과 지역 문장을 지역 관계로 결합하지 않는다. 관계 양쪽이 들어 있는 **동일 인용 블록**에서 불일치·격차·반면·함께·활용 등 명시 표현이 있어야 이슈 검토 대상으로 삼는다. 관계 부정(예: 불일치는 없다)이 있으면 승격을 보류한다.

공간·접근·거리·분포·생활권·재사용·노후·활동 등 건축적 검토 단서가 추가로 필요하다. 단순한 인구 감소만으로 건축 이슈를 만들지 않는다. 결과는 원문 관계에 대한 검토 질문이며 가능한 원인·효과를 새로 생성하지 않는다. CAUSAL 관계는 현 구현에서 생성하지 않는다.

LIVE 이슈에는 인용문에 실제 포함된 extracted claim, 시설 관련성 평가 60 이상, 평가 완성도 60% 이상의 자료가 필요하다. 현재 제공자는 원문 추출·의미 평가를 수행하지 않으므로 **실제 LIVE 메타데이터만으로는 이슈 도출이 보류되는 것이 정상**이다. “현재 근거만으로 건축 이슈를 도출하기 어렵습니다”를 보여주고 발견 자료는 모두 유지한다. LLM·새 원문 수집 서비스를 추가하지 않았다.

DEMO는 기존 demo provider의 가상 생활권 이동·분포 시나리오를 같은 분석 경로로 읽는다. 실제 통계·기관·URL·발행일을 만들지 않는다. 이슈 confidence는 항상 INSUFFICIENT이고 문제 정의의 사실 항목은 판단 보류다. 시험용 강한 LIVE 형태의 데이터는 서비스 테스트에만 있으며 앱에 삽입하지 않는다.

## 이슈 확신도

`issues/config.ts`가 기준을 보관한다. 출처 그룹은 #5의 기관·도메인·동일 제목 묶음을 재사용하며 실제 독립성의 대리 지표다. 대표 1건/출처, 최대 2건/자료 유형으로 강도 평균을 계산한다.

- HIGH: 출처 그룹 ≥4, 대표 자료 유형 ≥3, 근거 강도 ≥80, 현상 최소 확신도 ≥80, 관계 최소 확신도 ≥80, 관계 양쪽의 지역 연결.
- MEDIUM: 각각 ≥2, ≥2, ≥65, ≥65, ≥65와 지역 연결.
- LOW: 인용·관련성 요건을 통과한 자료는 있지만 위 조건 미달.
- INSUFFICIENT: DEMO 또는 평가 가능한 자료 없음.

현상·관계 확신도는 적격 출처 대표의 근거 강도 평균이며, 이슈에는 관련 현상과 관계 중 최소값을 사용한다. 관계를 별도로 검증한 통계적 확률은 아니다. 기존 WEAKENS_NEED 자료는 상반 신호로 보존하며 HIGH→MEDIUM→LOW로 한 단계 낮춘다. 수요 지지/약화는 이전 평가 계약이고, 동일 명제에 대한 논리적 모순과 동일하지 않다.

## 이슈를 먼저 선택하는 지역 탐색

`IssueExplorer`에서 사용자가 이슈를 선택해야 `GeographicOverview`가 렌더링된다. `mapIssueEvidence`는 이슈의 evidenceIds만 #5 mapper에 전달하고, 관계 양쪽에 명시된 공통 지역만 남긴다. 전국 배경·미확인 위치는 별도로 유지한다. 이후 지도·목록·상세 선택은 기존 구조를 재사용한다.

UI 점수 이름은 **Issue Signal**이다. 내부 `candidateScore` 계약과 #5의 가용 축 동일 평균을 보존한다. 이 값은 연결 자료의 강도·직접성·다양성·지역 구체성 요약이며, 관계의 진위나 부지 적합성을 증명하지 않는다. 이슈 확신도와 지역 Confidence를 별도로 표시한다. 원래의 근거 목록 필터가 이슈 결과나 점수를 바꾸지 않는다.

## 추적과 한계

이슈 → relationshipIds → phenomenonA/B → passages/evidenceIds → EvidenceItem → 원문 URL.
지역 → 이슈 연결 EvidenceItem → 원문 URL.
문제 정의 → 문장 → claimIds → 인용·evidenceIds → 원문 URL.

모든 원래 근거, 상반 신호, 점수에서 제외된 반복 자료를 유지한다. 아직 의미적으로 같은 문장의 완전한 병합, 관계의 시간·공간 단위 검증, 다문서 관계 추론, 전국 행정구역 사전·정밀 GIS는 없다. 쿼리에서 비롯된 현상이나 단순한 동시 언급을 확정 이슈로 승격하지 않는다. 입지·필지 선정, 프로그래밍, 설계 생성과 다음 단계는 구현하지 않는다.
