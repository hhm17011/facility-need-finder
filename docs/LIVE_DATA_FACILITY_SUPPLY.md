# LIVE DATA #3 — SIGUNGU Facility Supply

## 선택한 공식 출처와 확인 내용

한국사회보장정보원/어린이집정보공개포털의 [어린이집별 기본정보 조회](https://info.childcare.go.kr/info/oais/openapi/OpenApiInfoSl.jsp?flag=VIEW&svcseq=82), `cpmsapi030`을 사용합니다. [공식 기술문서 v1.7](https://info.childcare.go.kr/info/oais/common/FileDownload.jsp?flag=OPENAPIFILE&svcseq=82)을 확인했습니다. 공공데이터포털의 [전국어린이집표준데이터](https://www.data.go.kr/data/15013108/standard.do)도 제공기관·항목을 설명합니다.

공식 상세의 갱신은 비정기(수시)이며 데이터포털 메타데이터 수정일은 2025-08-20입니다. 이를 데이터 기준일로 대체하지 않습니다. `datastdrdt` 실제 응답 필드를 사용합니다. 과거 시점 요청 파라미터가 문서에 없어 역사 수치는 구현하지 않았습니다.

021 서비스보다 030을 선택한 이유는 시군구 단위 일괄 조회에 운영현황·정원·현원·데이터 기준일이 있어 활성 시설의 정의와 합계를 검증할 수 있기 때문입니다. 인증된 `key`와 `arcode`(시군구 코드)가 필요하고 `stcode`는 선택 항목입니다. 인증 없이 HTTPS 엔드포인트에서 공식 `ERROR-100` XML 응답을 수신하여 접속 경로를 확인했습니다. **이는 실제 시설 데이터 수신 또는 LIVE 검증 성공이 아닙니다.** 문서의 예시 인증키는 사용하지 않았습니다.

서버 환경변수 `CHILDCARE_API_KEY`에 승인된 키를 설정하고 재시작합니다. 누락 시 `LIVE VALIDATION BLOCKED — API KEY REQUIRED`로 표시합니다. HTTPS만 사용하며 요청 URL/키/제공자 오류 전문을 브라우저나 로그에 노출하지 않습니다. 개발가이드 상세의 출처표시 및 이용허락조건을 보존하며, 배포는 이번 범위가 아닙니다.

## 구조와 필드

`FacilitySupplyRequirement` → `FacilityDataSourceRegistry` → `FacilitySupplyProvider` → `ChildcareFacilityProvider` → `FacilityRecord` → `FacilitySupplyMetric` → 동일 시군구 수요/공급 지표 → RegionEvidenceProfile → 지도/상세.

첫 구현은 어린이집이며 노인복지관/청소년시설/도서관 등은 명시적으로 MISSING입니다. 타 시설을 어린이집 공급과 비교하지 않습니다.

문서로 확인한 사용 필드: `stcode`, `crname`, `sidoname`, `sigunguname`, `crstatusname`, `craddr`, `crcapat`, `crchcnt`, `crcnfmdt`, `crabldt`, `datastdrdt`. XML 태그의 문서상 대소문자 차이는 소문자로 정규화합니다. 전화번호, 연락 담당자 등 분석과 관계없는 정보는 화면에 별도로 확장하지 않습니다. 원본 필드는 추적용으로 남습니다. 제공하지 않는 값은 null입니다.

현재 API는 선택한 시군구 한 번 조회 방식입니다. 전국 자동 256회 호출을 하지 않습니다. 각 조회는 그 지역 내 레코드를 일괄 수신합니다. 메모리 5분/최대 32지역 캐시, 동시 동일 요청 합치기, 순차 1.1초 간격, 15초 제한, 리다이렉트 금지, 실패 캐시 없음. XML의 외부 엔티티/DOCTYPE를 금지하고 문서의 평면 item 형식만 읽습니다. 빈 응답은 0개 시설로 바꾸지 않습니다.

## 지역·활성 시설 정의

동일 canonical SIGUNGU registry를 사용합니다. 시도 + 시군구 전체 이름을 정확히 매칭하며 중첩 시/구를 보존합니다. 단독 중구처럼 모호한 이름은 UNRESOLVED입니다. 제공자 시설 ID의 앞자리를 임의 행정 코드로 해석하지 않습니다. 명시 코드와 이름이 불일치하면 합계에 사용하지 않습니다.

`crstatusname`이 정상 또는 재개이고 폐지일이 없는 어린이집만 활성으로 인정합니다. 휴지·폐지·상태 미상은 제외합니다. 공급자는 고유 stcode를 보존하고 중복 제거합니다. 같은 ID의 지역/상태/정원/현원/기준일이 상충하면 그 ID를 제외하고 전체 집계도 검증 보류합니다.

원본 수/채택 수/제외 수/중복/상충 중복/지역 매핑 실패/정원 누락/상태 누락/기준일 누락과 조회 지역을 보고합니다. 알 수 없는 상태·매핑 실패·시설 ID 누락·서로 다른 기준일·불완전 응답이 있으면 완전한 지역 총계로 표시하지 않습니다. 전부 폐지된 자료만 있어 공통 기준일이 없는 경우도 임의 0을 출력하지 않습니다.

## 공급 지표

- FACILITY_COUNT: 검증된 활성 시설 개수.
- TOTAL_CAPACITY: 정원 누락 없는 활성 시설의 합계. 개소 수와 구별.
- CURRENT_USERS: 현원 누락 없는 활성 시설 합계.
- AVAILABLE_CAPACITY: 같은 자료의 정원 - 현원. 현원 초과·누락은 보류.
- UTILIZATION_RATE: 현원 / 정원 * 100. 0 분모 금지.
- OPENING_COUNT/CLOSURE_COUNT/FACILITY_COUNT_CHANGE: 현재 자료만으로 기간별 완전한 이력을 보증하지 못해 MISSING.

인가일/폐지일은 원본 사실로 남기지만 최신 목록의 일자만 세어 과거 개폐원 총계로 추정하지 않습니다. UI는 `시설 공급 변화 데이터 미연결`을 표시합니다.

## 수요/공급 관계

같은 시군구, 동일 기준일, LIVE, 명시 대상 인구 정의, 명/개소 단위의 호환 자료만 사용합니다. 월 단위 KOSIS 값과 다른 일자의 실시간 시설 데이터를 같은 현재 시점으로 간주하지 않습니다. 이 경우 비율은 N/A이며 별도 맥락으로 표시합니다.

구현한 식:

- 시설 / 대상인구 * 1000
- 정원 / 대상인구 * 1000
- 대상인구 / 시설
- 대상인구 / 정원

분모 0/null, 다른 시군구/시점/정의/단위, DEMO 또는 검증 미완료 자료는 계산하지 않습니다. 식·입력 지표 ID·출처·기준일을 보존합니다.

검증된 과거/현재 인구와 공급이 모두 들어온 경우 동일 기간·경계·시설 정의에서 증가/감소/유지 방향을 비교합니다. 수요 증가+공급 감소, 동반 증가, 동반 감소, 수요 유지+공급 감소, 수요 감소+공급 유지/증가를 서로 다른 관계로 보존합니다. 가능한 과잉도 탐색 레이블일 뿐 결론이 아닙니다. 현재 제공자는 시설 시계열을 공급하지 않아 실제 관계는 보류됩니다.

`structuredIssues`는 유효한 변화 관계에서 재배치·공간 공유·재사용·프로그램 전환을 조사할 건축적 질문을 생성합니다. 신축을 처방하지 않습니다. 관련성이 있는 선택 이슈만 관계를 사용하며 단순 공급 데이터 수신으로 Issue Signal을 높이지 않습니다. 독립적인 근거 강도 평가가 없으므로 점수는 N/A입니다.

## 화면과 한계

시군구 explorer에서 인구·변화·시설 수·정원·시설/1,000명·관계 상태를 함께 확인합니다. 누락은 N/A. 선택 지역 상세에서 원본 레코드, 필터 수, 집계식, 비율 입력, 현상, 부족한 근거를 추적할 수 있습니다. 지도는 인구/변화/시설/정원/비율/선택 이슈 레이어를 명시하며 NO DATA를 채우거나 보간하지 않습니다.

공급만/인구만/관계 확인/불충분/서로 다른 관계를 구분합니다. 지역 수요와 공급이 있어도 시설의 위치·접근성·이용 의향 자료 없이는 건축 필요나 최종 부지를 확정할 수 없습니다.

현재 환경에 KOSIS_API_KEY 및 CHILDCARE_API_KEY가 없으므로 실제 시설 레코드·실제 인구 비율·REAL SIGUNGU 사례는 제시할 수 없습니다. 미조회 256개 지역은 MISSING이며 unresolved 0은 원자료가 없다는 뜻입니다. 공급 API 연결 확인은 인증 오류 응답까지이고 데이터 LIVE 검증은 BLOCKED입니다. 테스트의 TEST ONLY 수치를 실제 사례로 사용하지 않습니다.

다음 필요한 근거는 같은 기준일·연령 정의에 맞는 공급 이력과 공간 분포/접근성·실제 이용 수요입니다. 이동·개발·필지·지목·설계·배포는 추가하지 않았습니다.


### LIVE DATA #3 보완 검증 (2026-09-21)

수요·공급 파생 지표는 동일 지표·단위·대상 인구 정의·인구 모집단·시설 정의·SIGUNGU 수준·기준일의 집단에서만 비교합니다. 2개 이상의 고유 지역에 중간 순위 백분위 `100 × (낮은 값 개수 + 동률 개수 / 2) / 집단 크기`를 적용합니다. DEMO, 비유한 값, 중복 지역은 비교에서 배제합니다. 상세 화면에서 원값·백분위·집단 크기·시점과 입력 호환성 사유를 확인할 수 있습니다. 시설 수 및 정원/1,000명 지도를 제공하며 자료가 없으면 N/A입니다.

공급 품질에는 정원·현원 누락 비율(활성 시설 분모), 기준일·운영 상태 확인 비율(고유 시설 분모)이 포함됩니다. 분모가 없으면 null입니다. 공급 집계는 시설 유형·제공자·데이터셋·활성 정의를 인자로 받으며, 첫 공식 제공자는 어린이집입니다. 검증된 관계는 기존 Phenomenon/PhenomenonRelationship 형식으로 연결하고 지역 상세에서 건축 질문 → 관계 → 현상 → 입력 지표 → 출처를 추적합니다. Issue Signal은 임의 가산하지 않습니다.

실제 인증키는 KOSIS·어린이집 모두 MISSING으로 확인했습니다. `LIVE VALIDATION BLOCKED — API KEY REQUIRED`. 현재 실제 시설 LIVE 지표 및 실제 사례는 없으며, 256개는 분석 가능한 행정구역 수이지 시설 데이터 확보 지역 수가 아닙니다.

최종 검증: `npm test` 전체 97개 통과(실패/건너뛰기 0), `npm run build` 타입 검사 및 프로덕션 빌드 통과. 번들 500 kB 초과 안내는 비차단 경고입니다. 로컬 개발 URL: http://127.0.0.1:5173/ . 실 API 데이터 검증과 브라우저 조작 검증은 이번 검증 결과에 포함하지 않습니다.
