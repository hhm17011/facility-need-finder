# Regional Evidence Engine

## 근거가 지도보다 먼저다

선택한 건축 이슈 → 지역 검증 질문 → 지역 발견 → 선택 지역 추가 검증 → 행정 단위 확인 → 비교 가능한 지표 → 직접 근거가 있는 시·군·구 → 실제 행정경계 지도 → 지역 상세.

행정경계 폴리곤, 기존 이슈의 지역 목록, 시·도 점수는 시·군·구를 만들어내지 않는다. 엔진은 실제 입력 EvidenceItem에서 명시 지명을 발견하고 검증한다. 전국·시도 근거만 있으면 새로운 하위 지역을 생성하지 않는다. TOP 50 상한/채우기 요구는 제거했다. 결과 0개도 정상이다.

## 계약과 파일

`frontend/services/regional/`:

- `types.ts`: RegionalEvidenceRequirement, AdministrativeLevel, RegionalObservation/Metric, RegionalDataGap, RegionalEvidenceLink, RegionalAssessment, RegionalEngineResult.
- `requirements.ts`: 시설·이슈별 검증 항목과 제한된 검색 쿼리.
- `administrative.ts`: 원문의 행정 단위와 상·하위 관계 판정.
- `metrics.ts`: 수치 원문·정의 확인, 비교 그룹, 파생지표.
- `engine.ts`: 발견/검증, coverage, status, confidence, Issue Signal, 지도 진입 조건.
- `discovery.ts`: 기존 서버 검색 API를 사용한 순차·중단 가능한 단계별 탐색.
- `config.ts`: 검색 상한·직접 근거 문턱·상태/확신도·가중치.

기존 RegionEvidenceProfile을 폐기하지 않고 `regionalAssessment`를 추가했다. 기존 `metrics`의 집계값과 혼동하지 않도록 지역 수치는 `regionalAssessment.regionalMetrics`에 보관한다. `candidateScore`는 호환 표시용으로 새 Issue Signal 값을 담는다. 새 상세는 새 산식만 표시한다. 이전 #5 점수 로직은 역사적 하위 모듈로 보존되지만 현재 지도 진입을 결정하지 않는다.

## 이슈별 근거 요구

인구 변화·도시 변화·시설 변화·수요/공급·공간 조건·지역 직접 조사 6개 차원을 유지하되, 이슈 유형에 따라 중요/보조 차원을 다르게 정한다. 예를 들어 접근성 이슈는 공간 조건·지역 조사를, 재사용 이슈는 시설 변화·공간 조건·지역 조사를 중요하게 본다. 질문의 시설·이용자·기능은 FacilityProfile에서 가져온다. 어느 시설에도 부족을 전제하지 않는다.

각 요구에는 지표 목록, 선호 SIGUNGU/허용 SIDO, 자료 유형, 질문을 저장한다. SIDO 허용은 배경 자료 보존을 의미하며 SIGUNGU 검증 충족을 의미하지 않는다.

## 발견과 추가 검증

- Stage A: 사용자가 ‘지역 근거 탐색’을 누르면 지역명 없는 광역 쿼리 최대 6개를 실행한다. 통계·공공 보고서·연구·지역 조사를 우선한다.
- Stage B: 실제 반환 자료에서 기존 보수적 지명 정규화기로 지역을 추출한다. 모호한 중구/광주는 추측하지 않는다.
- Stage C: 발견 목록에서 사용자가 최대 2개 시·군·구를 선택하고 ‘선택 지역 추가 검증’을 누른다. 지역당 최대 3개 쿼리다. 사전에 정한 좋은 지역 목록은 없다.
- Stage D: 동일 조건의 지역 지표만 비교 그룹으로 묶는다.

최대 6 + 2×3개 쿼리/두 단계 실행이며 기존 결과당 5개 상한·순차 큐·메모리 캐시를 재사용한다. 설정은 regional/config.ts에 있다. 지자체 전수 자동 검색은 없다. 기존 API에 제한된 regional 요청(issueType/stage/regionId)을 추가했고 서버가 쿼리를 다시 만든다. 임의 URL이나 자유 쿼리를 받지 않는다. 시설/모드/이슈 변경 시 검색은 중단되고 추가 결과를 폐기한다. 원래 EvidenceItem을 수정하지 않는다.

공급 현황, 이용률, 정원 충족률, 감소/증가, 충분/과잉, 폐쇄/신설, 이용/미이용을 포함한다. 검색어에 나타난 사실을 결과로 간주하지 않는다. 검색 목적만으로 자료를 관련성 확인 완료로 승격하지 않는다.

## 행정 단위와 역할

NATIONAL / SIDO / SIGUNGU / EUPMYEONDONG / UNKNOWN을 각 지역 근거 조각에 저장한다. `engine.evidenceLinks`는 아직 어느 프로필에도 들어가지 않은 UNKNOWN 조각도 보존한다.

- DIRECT: 원문 인용 또는 검증된 수치 행이 동일 지역·동일 행정 단위를 명시하고 시설 관련성 평가를 통과했다.
- PARENT_CONTEXT: 경기도→용인시/기흥구, 용인시→기흥구 등 명시 상위 지역 자료. 직접 지표/coverage/점수에 포함하지 않는다.
- NATIONAL_CONTEXT: 전국 자료. 모든 지역에 분배하거나 점수 가산하지 않는다.
- UNKNOWN: 단순 언급·스니펫·미평가 관련성·복수/불명확 범위·단위 불일치.

제공된 지리 범위가 명확하면 우선한다. 경기도 통계에 용인시가 부수적으로 등장해도 직접 근거가 되지 않는다. ‘기흥구 보정동’ 같은 더 세밀한 단위는 구 전체 수치로 올리지 않는다. 현재 읍면동 사전/집계는 없으므로 관련 검증은 보류한다.

전국 데이터셋이라도 **지역명·값이 명시된 검증된 시군구 행**이 별도로 있으면 그 행만 해당 지역 DIRECT가 될 수 있다. 전국 총계를 분배하는 것과 구별한다.

## 직접 근거와 지도 진입

원문 추출 인용은 원문에 문자 그대로 포함되어야 하며, 시설·이용자·기능 단서 및 선택 이슈의 중요 검증 차원과 연결되어야 한다. 기존 관련성 평가 evaluated ≥60, 평가 완성도 ≥60%를 요구한다. 검색 제목/요약만 있는 문서는 발견용이다. 수치 행은 아래 검증 계약을 충족해야 한다. 현재 DEMO는 실제 지역의 직접 근거로 승격하지 않는다.

정규화된 SIGUNGU + 최소 1건의 직접 지역 근거 + 선택 이슈/해당 검증 검색과의 연결이 있으면 evidence-supported로 표시한다. 모든 차원을 완성할 필요는 없다. 기존 source role의 DIRECT(시설 필요성 직접성)와 새 geographicEvidenceRole의 DIRECT(행정 범위 일치)는 다른 개념이다.

상태:

- INSUFFICIENT: 시군구 직접 근거 없음. Issue Signal N/A. 발견 목록·배경에는 남고 지도 신호에서 제외.
- PARTIALLY_SUPPORTED: 직접 근거는 있으나 중요 차원이나 출처 교차 확인 부족.
- SUPPORTED: 상한 적용 출처 대표 ≥2, 직접 차원 ≥2, 이슈의 중요 차원 충족.
- CONFLICTING: 강한(≥75) 수요 지지/약화 자료가 함께 있거나, 동일 지역·정의·시점 수치가 서로 다름. 지도에서 제외하지 않는다. 수요 방향 차이는 같은 명제의 논리적 모순이라고 단정하지 않는다.

`RegionalEngineResult.supportedRegions`만 KoreaMap에 전달한다. 지도 join도 regionalAssessment가 INSUFFICIENT인 프로필은 배제한다. 지도 파일은 기존 실제 17개 시·도 경계를 유지한다. 자료 없는 경계는 중립, 일부 확인은 황색, 확인은 녹색, 상충은 적색 계열이다. 하위 지역 최대 Issue Signal로 시·도 색을 표시한다는 기존 규칙을 유지하고 시·도 자체 점수와 구별한다. SIGUNGU 경계 드릴다운은 아직 없다.

## 수치와 비교

`regionalObservations`는 원문 확인된 표/공공 데이터 어댑터용 계약이다. 값, 단위, 지역, 행정 단위, 기준 시점, 지표 정의, 모집단 정의, 분모, 경계 기준, sourceExcerpt/sourceLocator, 검증 상태를 보관한다. 원문에 지역과 값이 존재해야 한다. 누락값·무한값·잘못된 날짜는 보류한다. 현재 검색 제공자가 이 필드를 자동으로 채우지 않는다.

기존 quantitativeEvidence는 지표/값/단위/시점/인용을 잃지 않도록 UNKNOWN 차원의 미검증 지표로 보존한다. 없던 정의·분모·수치를 생성하지 않는다.

비교 그룹은 아래 필드가 **모두 동일**하고 서로 다른 지역이 2개 이상일 때만 만든다:

`metricType + administrativeLevel + administrativeUnit + referenceDate + unit + definition + populationDefinition + denominator + boundaryVersion`

SIGUNGU 내부의 시/군과 구도 구분한다. 비슷한 연도라고 임의로 허용하지 않는다. 시점이 다르면 “비교 자료의 기준연도가 다릅니다”를 표시하고 그룹을 분리한다. 정원과 개소 수, 사람과 %, 다른 모집단을 하나의 비교축에 놓지 않는다. 동일 지역의 상충 수치는 원문들과 함께 보존하고 비교 그룹에서 제외한다. 단일 지역의 유효 지표는 타 지역 비교가 불가능해도 해당 지역 직접 근거일 수 있다.

## 파생지표

현재 구현은 **대상인구 1,000명당 시설 수** 하나다:

`facility_count / target_population * 1000`

동일 지역·행정 단위·시점·모집단·분모·경계 기준, 명/개소 단위, 원문 검증과 지표 정의가 필요하다. 인구 0, 누락값, 음수 개소 수, 상충 수치, 다른 연도는 계산하지 않는다. 결과에는 formula, input metric IDs, source evidence IDs, reference years를 저장한다. 이 비율로 부족/과잉 기준을 임의로 결정하지 않는다.

## Issue Signal과 Confidence

시군구 직접 근거가 없거나 직접 근거 강도가 전부 미평가면 Issue Signal은 null/N/A다. 나머지는 아래 **가용 축 동일 가중 평균**이며 가중치는 config.ts에 있다:

1. strength: 직접 근거 대표의 evidenceStrength 평균.
2. coverage: 직접 확인 차원 수 / 6 ×100. 미확인 차원도 분모에 남는다.
3. relationship: 선택 이슈의 기존 근거에 속하고 직접 발췌에 명시 관계 표현이 있으면 100, 없으면 미평가. 관계 진위를 검증한 확률은 아니다.
4. comparability: 지역 지표 중 비교 그룹에 포함된 비율 ×100. 지표 자체가 없으면 미평가.
5. sourceDiversity: 식별 가능한 직접 출처 대표 / 3 ×100, 최대100.
6. completeness: 직접 출처 대표의 기존 평가 완성도 평균 ×100.

출처 기관·도메인·동일 제목 묶음당 대표 1개, 자료 유형당 최대 2개를 재사용한다. 기사 수 합산은 하지 않는다. 상반 자료는 삭제/일괄 차감하지 않고 별도 표시하며 확신도를 LOW로 낮춘다. 점수와 원자료/산식은 모두 펼쳐 확인할 수 있다.

Confidence: INSUFFICIENT는 직접 근거 없음. 기본 적격 지역은 LOW. SUPPORTED이며 coverage ≥50%면 MEDIUM. SUPPORTED + 상한 적용 식별 출처 ≥4 + coverage ≥80% + 비교 가능한 지표 + 명시 관계 근거면 HIGH. 상충/수요 약화 자료가 있으면 LOW. 과학적 검증이나 최적 입지·건설 필요성 판정이 아니다.

## UI와 추적

지역 상세는 숫자보다 먼저 ‘왜 이 지역이 지도에 표시되었는가?’를 설명한다. 이슈 → 지역 현상 인용 → coverage(✓/△/✕) → 수치와 시점 → 직접/상충/상위/전국 근거 → 데이터 부족 → 원문으로 이어진다. 근거 유형 필터는 점수를 재계산하지 않는다. 새 지역 근거도 기존 문제 정의 입력에 전달하되 전국·상위 범위는 그대로 보존한다.

지도 → RegionalEvidenceProfile.regionalAssessment → RegionalMetric/RegionalEvidenceLink → EvidenceItem → URL.
점수 → scoreDimensions → 대표/제외 evidence IDs → 원문.

## 현재 한계

- 기본 화면은 DEMO이다. 직접 근거 0, 비교 그룹 0, 지도 중립은 정상 결과다.
- LIVE API 키가 없는 환경에서 실제 검색 왕복은 미검증이다. DEMO 요청으로 새 검색 경로·제한을 검증했다.
- LIVE 제공자는 검색 메타데이터를 반환하며 표 자동 수집·수치 원문 검증·관련성 의미 평가가 아직 연결되지 않았다. 전국 지자체를 비교하는 통계 어댑터를 추가한 것으로 주장하지 않는다.
- 기존 소규모 지명 사전만 사용한다. 미등록/모호한 지역은 제외하고 확인 필요로 보존한다. 행정코드를 임의로 생성하지 않는다.
- 정량 비교는 정확한 동일 조건만 허용한다. 연도 보간·단위 변환·행정경계 변화 보정은 없다.
- 원문 관계·모집단·통계 방법의 실질적 품질 검토는 별도 과제다.
- 지도는 실제 지리 데이터의 2021년 시·도 경계이며 시군구 경계·읍면동 집계는 미구현이다.
- 필지 선정·토지 적합성·건축 설계·AHP·배포는 구현하지 않는다.
