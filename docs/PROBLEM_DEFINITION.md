# Architectural Problem Definition

#6의 근거 우선 생성·수정·항목별 재생성을 구현하고, 이후 아키텍처 개편 요청에 맞춰 입력에 `Selected ArchitecturalIssue`를 추가했다. 이전 WHY FACILITY/NOW/REGION 구조는 현재 BACKGROUND/PHENOMENA/ARCHITECTURAL ISSUE/REGIONAL EXPRESSION/DESIGN QUESTION으로 대체했다.

## 입력과 생성 순서

FacilityProfile + 선택 이슈 + 선택 지역(없을 수 있음) + 이슈에 연결된 전국 배경/지역 근거.

EvidenceItem → exact claim 추출 → 중복 병합 → 사용 가능성 검사 → 전국/지역·지지/상반 분리 → 항목별 선택 → 인용문과 열린 질문.

`collectEvidence`는 선택 이슈의 evidenceIds와 현재 모드만 받는다. `extractClaims`는 sourceExcerpt 안에 실제 포함된 extracted claim을 문장 단위로 나눈다. 원문과 다른 추출 문장은 버리고 제목/스니펫 인용 후보로 대체한다. 메타데이터 인용은 검토 목록에 보존하되 사실 항목 작성에는 사용하지 않는다. 수치 토큰은 원문에 있는 값만 보존하며 검증된 통계라고 표시하지 않는다.

정규화한 동일 문장·범위·stance를 하나로 묶고 출처 ID를 모두 보존한다. 수치가 다른 주장, 방향이 다른 주장, 전국/지역을 합치지 않는다. 의미적 유사성을 추측해 서로 다른 주장을 병합하지 않는다.

## Claim Strength

`problemDefinition/config.ts`의 동일 가중치로 가용 축을 평균한다:

1. 출처 대표의 기존 evidenceStrength 평균.
2. 식별 가능한 대표 출처 수 / 3 ×100, 최대100.
3. 역할이 판정된 대표 중 DIRECT 비율 ×100.
4. 인용 자체가 선택 지역을 명시하면 시·군·구100 / 광역60. 전국·미확인은 결측으로 제외.

기존 #5의 동일 기관/도메인/제목 그룹 대표 1건, 같은 자료 유형 최대 2건을 재사용한다. 평가 강도가 전혀 없으면 점수는 null이다. 원문 수나 반복 기사 수로 점수를 올리지 않는다. 상반 근거 ID는 별도 보존하며 점수에서 일괄 차감하지 않는다. 해당 주장을 반박한다고 자동 판정하지도 않는다. 점수는 과학적으로 검증된 값이 아니다.

실제 문장에 사용하려면 LIVE, 원문 인용 추출, 알려진 범위, 대표 모두 관련성 ≥60·평가 완성도 ≥60%, 알려진 역할, Claim Strength ≥60이 필요하다. 360자보다 긴 주장은 검토 목록에 남기고 간결한 발표 항목에서는 보류한다. UNKNOWN/DEMO/메타데이터는 강도를 계산하더라도 실제 사실 문장을 만들지 않는다.

## 전국·지역과 시간

전국 근거는 배경과 현상 항목에서만 인용 가능하며 지역 표현 항목에 사용하지 않는다. 지역 주장은 문장 자체가 선택 지역을 명시해야 한다. 문서 제목에 지역 이름이 있다는 이유만으로 문서의 모든 주장을 해당 지역의 사실로 간주하지 않는다. 다지역 문장은 보수적으로 보류한다.

BACKGROUND의 변화·유지 표현에는 발행일이 확인된 최근 36개월 자료를 우선 사용한다. 발견일을 발행일로 대체하지 않는다. 시점이 없거나 오래된 자료만 있으면 최신성 부족을 표시한다. 같은 날짜를 재생성에서도 유지한다. “위기”나 부족을 새로 서술하지 않는다.

## 출력·편집·추적

5개 발표 항목은 기본 최대 2개 주장 인용과 필요한 한계/질문으로 짧게 구성한다. 지원되지 않으면 “현재 확보된 근거만으로는 판단이 어렵습니다.”를 출력한다. 상반 주장이 있으면 지지/배경 주장의 나열만으로 끝내지 않고 함께 인용한다. DESIGN QUESTION은 사실 단정이나 신축 답을 포함하지 않는 열린 질문이다.

각 사실 문장은 statements[].claimIds/evidenceIds를 가진다. UI 출처 칩 → 해당 EvidenceItem 카드 → 원문 URL. 펼친 추적 영역에는 주장·인용 필드·원문 위치·산식을 표시한다. DEMO는 URL을 생성하지 않는다.

사용자는 제목·본문·설계 질문을 수정할 수 있다. `SectionDraft`는 생성 원문과 분리하며 “사용자 수정 · 근거 일치 미검증”으로 표시한다. 출처 칩은 생성 원문에 대한 연결이라는 점을 명시한다. 수정은 EvidenceItem이나 원래 생성 결과를 변경하지 않는다. 항목 다시 생성은 클릭 당시 동결한 ProblemInput 스냅샷으로 해당 항목만 복원하고, 다른 수정은 보존한다. 재검색/추가 API 요청은 없다. 시설·모드·이슈·선택 지역 변경 시 초안을 초기화한다. 페이지 저장 기능은 없다.

`gaps`에 미지원 항목, 저확신 주장, 결측 자료 유형, 지역 근거 부족, 오래된/날짜 미확인 자료를 보존한다. 다음 단계의 전체 Gap Detector는 구현하지 않는다.

## 현재 DEMO 예

이슈: 어린이집 · 생활권과 시설 분포. 선택 지역: 경기도 용인시(가상 시나리오).

- BACKGROUND / PHENOMENA / ARCHITECTURAL ISSUE / REGIONAL EXPRESSION: 현재 확보된 근거만으로는 판단이 어렵습니다.
- DESIGN QUESTION: 경기도 용인시에서 어린이집의 공간적 역할을 시설 분포·입지 관점에서 어떻게 검토할 수 있는가?

가상 예를 실제 지역 문제로 작성하지 않는 것이 의도된 동작이다. 실제 원문 추출과 관련성 판정이 확보되면 해당 문장을 출처와 함께 인용한다. 추가 근거 탐색·부지 선택·PPT/PDF 내보내기는 하지 않는다.
