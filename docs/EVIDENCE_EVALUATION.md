# Evidence Evaluation — #4

## 목적과 한계

현재 설계 문제를 검토할 때 어떤 자료를 먼저 살펴볼지 돕는 **메타데이터 기반 시제품 평가**입니다. 지역 순위, 시설 건립의 타당성, 최종 추천 또는 검증된 증거 품질 지수가 아닙니다. 유형별 고정 점수는 사용하지 않습니다.

현재 입력은 #3에서 받은 제목·스니펫·출처 메타데이터입니다. 모든 결과에 `analysisDepth: metadata_only`를 붙입니다. 원문 전문·수치의 정확성·설문 방법·기관 진위·동료심사·법령의 현행성을 검증하지 않습니다. 결과에 그 한계를 표시합니다.

## 서비스와 데이터

```text
EvidenceItem[] + FacilityProfile + EvidenceSearchPlan
  → URL 중복 제거
  → deterministic.ts: 관찰 가능한 메타데이터 신호
  → semantic.ts: 의미 분석 계약, 현재는 미연결 fallback
  → evidenceAnalyzer.ts: 항목별 점수·이유·가용 항목 평균
  → EvaluatedEvidenceItem[]
  → selection.ts: 정렬·요약·필터·Top Evidence
  → UI: 근거 강도 / 평가 완성도 / 펼침 설명
```

`analyzeEvidence(item, profile, plan?, options?)`는 원문 객체를 변경하지 않습니다. `evaluation`을 설명이 있는 평가로 확장하고 원문 URL, 발행일, 제공자, 모드, 제목·스니펫, 지역 언급, 범위, 분류, 검색어, 기존 추출 필드를 유지합니다. #3의 원본 `EvidenceItem.evaluation`은 계속 null이며, #4 타입은 별도입니다.

모든 항목은 `score`, `status`, `reason`, `method`, `signals`를 갖습니다. 미평가 상태는 `unknown`, `requires_source_verification`, `requires_semantic_analysis`로 구분합니다. `evaluationVersion`에 해당하는 필드는 `analysisVersion`이며 현재 `metadata-rules-v1`입니다. 평가 기준 시각도 보존합니다.

## 다섯 평가 항목

### 신뢰성 — 규칙 기반 출처 식별·추적 가능성의 대리 지표

추적 가능한 원문 URL과 기관 또는 사이트 표시명이 모두 있어야 평가합니다. URL/도메인만 있으면 미평가입니다.

- 기관 메타데이터 50 또는 사이트 표시명 30 중 하나
- 원문 URL +10
- 위 식별 정보가 있는 경우에만 `.go.kr` 형태 +10
- 미래가 아닌 유효한 발행일 +5
- 제목·스니펫에 조사 대상/표본 표현과 수량이 함께 있으면 +10
- 상한 85

각 가점 신호를 펼침 설명에 표시합니다. 기관 메타데이터와 사이트 표시명은 구분하며, `.go.kr` 형태가 공식 기관의 발행이나 자료의 진위를 보장하지 않습니다. 표본 표현도 방법론 검증이 아닙니다. 학술 카테고리나 도메인으로 동료심사를 주장하지 않습니다.

### 관련성 — 현재 미평가

외부 의미 분석기를 연결하지 않았으므로 점수는 null, 상태는 `requires_semantic_analysis`입니다. 시설명·주요/관련 이용자·기능·문제 영역·탐색 주제와 일치하는 표현은 관찰 목록으로만 보여주고 점수로 바꾸지 않습니다.

`SemanticAnalyzer` 계약은 자료, FacilityProfile, EvidenceSearchPlan을 전달받습니다. 미래 어댑터 응답은 0–100 점수·설명과 실제 제목/스니펫에 존재하는 인용을 제공해야 합니다. 응답 오류·범위 밖 점수·없는 인용은 미평가로 되돌립니다. 인용의 문자 일치 검증만으로 의미 판정의 타당성이 보증되지는 않습니다. 현재 실행에서는 이 어댑터를 사용하지 않습니다.

### 최신성 — 날짜와 맥락 규칙

`publishedDate`만 사용합니다. 없거나 잘못되었거나 평가 기준일보다 미래이면 null입니다. 발견 시각과 Brave의 발행/수정 혼합 날짜를 대용하지 않습니다.

| 임시 탐색 맥락 | 경과기간 구간 → 점수 |
| --- | --- |
| 통계·수요조사·설문·기사 | 1년 이내 100 / 3년 이내 75 / 5년 이내 50 / 이후 25 |
| 연구 또는 기초·이론 표현 | 2년 이내 100 / 5년 이내 85 / 10년 이내 70 / 이후 55 |
| 일반 자료 | 2년 이내 100 / 5년 이내 75 / 10년 이내 50 / 이후 30 |

복수 탐색 유형이 겹치면 현황 자료의 짧은 구간을 먼저 적용합니다. 분류가 임시라는 한계를 설명합니다. 오래된 연구를 자동 폐기하지 않으며 내용의 가치를 날짜만으로 판정하지 않습니다.

법률·법령·시행령·시행규칙·조례 표현이 있으면 발행일이 있어도 현행성 확인 전까지 미평가로 남깁니다. 오래된 제정일에 낮은 점수를 주거나, '현행' 단어만으로 현재 효력을 확정하지 않습니다.

### 지역 구체성 — 명시 지명의 해상도

- 제목·스니펫에 시·군·구 이하 지명이 명시되면 90
- 광역시·도 지명은 60
- 명시적인 전국 범위는 25
- 없으면 null

예를 들어 `광주광역시 북구`는 `광주광역시`만 있는 경우보다 구체적으로 처리합니다. #3의 제한된 지명 목록 및 명시적인 광역/하위 지명 패턴만 사용하므로 누락될 수 있습니다. 지명 언급은 지역 수요의 직접 증거가 아닙니다. `regionalLevel`에 관찰 수준을 저장하되 지역 추천·행정코드·GIS 분석을 하지 않습니다. 전국 자료도 보존합니다.

### 근거 구체성 — 텍스트에 실제 있는 표현

텍스트가 너무 적으면 null입니다. 평가 가능한 텍스트의 기본값은 15이며 다음 표현이 실제 있을 때만 가점합니다.

- `%`, `명`, `개소`, `가구`, `세대`, `곳`, `건`을 동반한 수량 +25
- 수량과 조사 대상/표본 표현 +20
- 수량과 변화·비교 표현 +20
- 명시적인 조사/연구 결과 또는 설치/확보 요구 표현 +15
- 홍보성 표현 −15
- 0–95 범위

연도만으로 수치 근거로 인정하지 않습니다. 수치·통계를 생성하거나 `quantitativeEvidence`에 추정값을 추가하지 않습니다. 단어 존재의 대리 평가이므로 해당 문장이 부정되었는지, 인용되었는지, 연구 결론이 타당한지는 판단하지 않습니다. 따라서 관련성·직접성·수요 방향 판정을 대체하지 않습니다.

## 근거 강도와 결측값

기본 가중치는 다섯 항목 모두 1입니다.

```text
근거 강도 = 평가된 항목 점수의 합 / 평가된 항목 수
```

소수점 첫째 자리로 반올림합니다. null은 분자·분모 모두에서 제외하고 **0점으로 바꾸지 않습니다**. 실제 평가된 0점은 평균에 포함됩니다. 평가 가능한 항목이 없으면 종합 점수도 null입니다.

가령 산술 예시로 80, 60, null, 40, null이면 `(80 + 60 + 40) / 3 = 60.0`, 평가 완성도는 `3 / 5`입니다. 이 수치는 실제 자료의 결과가 아닙니다. 항목별 이름·점수·가중치·합·분모·빠진 항목을 UI에서 확인할 수 있습니다.

`EvidenceWeightConfig`로 이후 가중치를 교체할 수 있습니다. 현재 UI는 기본 동일 가중치만 사용합니다. 설정된 0 가중치는 평균에서 제외하고 별도 기록합니다. 음수/비유한 설정은 해당 항목의 기본값으로 되돌립니다. 유효 가중치 합이 0이면 종합 점수는 null입니다. 항목 가용성(완성도)과 가중치로 인한 제외는 분리합니다. AHP나 전문가 합의로 검증된 모델이 아닙니다.

## 라벨과 검토 우선 근거

모든 점수·기간·라벨·선정 임계값은 `frontend/services/evidence/analysis/config.ts`에 있습니다.

- 종합 점수 없음 또는 평가 항목 3개 미만: **평가 정보 부족**
- 75점 이상 및 4개 이상 평가: **강한 근거**
- 그 외 55점 이상 및 3개 이상 평가: **보조 근거**
- 나머지: **참고 자료**

라벨은 메타데이터 기준입니다. 의미 관련성이 미평가여도 다른 4개 항목으로 강한 라벨이 나올 수 있으므로 직접성 미판정, 완성도, 분석 깊이를 항상 함께 표시합니다. '맥락 자료'는 강도 라벨과 혼동하지 않도록 별도의 의미 역할에만 사용합니다.

Top Evidence는 현재 필터 내 70점 이상, 4개 이상 평가된 자료에서 최대 5개를 고릅니다. 남은 최고 점수와 5점 이내인 후보들 사이에서 새로운 탐색 유형을 우선합니다. 다양성을 위해 낮은 품질의 기사를 끼워 넣지 않습니다. 자격 있는 자료가 1개면 1개만, 없으면 빈 목록과 이유를 보여줍니다. 강도 계산식은 바꾸지 않습니다.

## 직접성, 맥락, 상반된 근거

`evidenceRole`: DIRECT / CONTEXT / UNKNOWN

`stance`: SUPPORTS_NEED / WEAKENS_NEED / NEUTRAL / UNKNOWN

현재 의미 분석기가 없으므로 두 필드는 UNKNOWN이며 이유를 보존합니다. 시설명이 등장한다고 DIRECT로 분류하거나, '감소'라는 단어만으로 수요 약화로 판단하지 않습니다. 미래 어댑터는 각각의 판단과 근거 인용을 반환할 수 있습니다.

시스템은 시설 건립을 정당화하는 자료만 찾도록 설계하지 않습니다. 수요 감소, 충분한 기존 공급, 유휴 시설, 기존 주장과 충돌하는 자료를 보존합니다. 탐색 계획의 뉴스·조사 주제에도 수요 변화·이용 감소·미이용 이유를 포함했습니다. 수요 지지 여부는 강도 정렬·Top Evidence 자격·기본 필터에서 배제 기준이 아닙니다.

## 화면과 요약

기본 정렬은 근거 강도순이며 최신순(발행일 미상은 뒤), 유형순도 제공합니다. 원래 유형·지명 필터를 유지하고 강한/직접/지역 근거 필터를 추가했습니다. 직접 근거 필터가 비어 있는 것은 의미 판정 미실행일 수 있으며 '직접 근거가 존재하지 않는다'는 결론이 아닙니다.

요약은 전체 현재 근거에서 산출합니다. 총 근거, 강한 근거, 직접 지역 근거, 맥락 자료, 평가 정보 부족, 직접성 미판정 수를 보여줍니다. Top Evidence는 현재 필터 결과 기준입니다. 수집 중에는 도착한 자료부터 평가하고, 모드 변경·재탐색 때 기존 평가와 필터도 초기화합니다.

DEMO는 가상 표시와 null 원문 URL을 유지하며 점수 옆에도 DEMO를 표시합니다. LIVE는 반환된 메타데이터만 평가합니다. 현재 API 키가 없으므로 실제 LIVE 왕복은 검증하지 못했고 테스트 전용 응답으로 LIVE 카드 표시·원문 URL 보존을 확인합니다.

## 검증과 다음 단계 경계

`npm run build`, `npm test`로 기존 #3 및 #4 서비스 테스트를 실행합니다. 출처 정보가 많은 자료, 연구/최근 기사, 날짜/지역 없음, 약한 메타데이터, 중복, 수요 감소 자료, DEMO, 가중치·결측값, 정렬·선정·의미 어댑터 오류를 검증합니다. 브라우저에서는 접힌 평가 설명, 계산식, 필터·정렬·건수·원문 링크·모바일 동작을 확인합니다.

다음 단계에 필요한 원문·발행일·유형·지역 언급·범위·강도·역할·stance를 유지합니다. #5 지역 연결, 지역 순위, 최종 입지 추천은 이번 단계에 포함하지 않습니다.
